# 技術的ブロッカーの記録（`G-BLOCKER`）

ライブラリ由来の failure（クラッシュ・原因不明の性能劣化）に遭遇したら、
**回避策で先に進むのは正しいが、回避した時点で記録を止めない**。
止めると次のコンペで同じ壁に同じ時間をかける（過去コンペではブロッカー 4 件を
いずれも原因未特定のまま回避し、約 100 分を費やして知識が何も残らなかった = L-12）。

1 ブロッカー = 1 ディレクトリ（`{日付}_{ライブラリ}_{症状}/`）で以下を残す:

- `repro.py` — **最小再現コード**
- `NOTES.md` — ライブラリのバージョン・スタックトレース・試した回避策・upstream issue の URL

回避策を採った場合も **未解決の技術的負債として `TODO_TEMPLATE.md` に残す**。
同じライブラリを次に使う前に `PLAYBOOK.md` の「既知の落とし穴」を確認すること。
